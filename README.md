# Моніторинг насосних станцій

Angular 22.2.2, TypeScript 6, standalone-компоненти, signals, OnPush та zoneless change detection. Інтерфейс, дані й правила розрахунку перенесено з наданого HTML-прототипу.

## Запуск

Потрібен Node.js 22.22.3+ у гілці 22 (перевірено на 22.23.2) та npm.

```sh
npm ci
npm start
```

Відкрийте http://localhost:4200. Демо-логін: `admin`, пароль: `admin`.

## Можливості

- Три станції Житомира з початковими синтетичними наборами за 01.01–22.07.2026.
- Зведення стану мережі, витрата й тиск на картках станцій та зріз показників опорної доби в деталізації.
- Темна тема, адаптивні картки, керування графіками з клавіатури; форматування показників виконується в TS.
- Карта Leaflet з тайлами OpenStreetMap у темному оформленні, переходом до станції та доступними текстовими посиланнями.
- Чотири графіки Chart.js, повноекранний перегляд, закриття кнопкою або Escape.
- Період дат, таблиця добових показників та архів сповіщень із фільтром статусу.
- Невідомі станції, неправильний період та порожні результати обробляються окремо.

## Структура

```text
src/app/core/auth/              демо-сесія, guards
src/app/features/login/components/login/ форма входу
src/app/features/login/config/  тексти форми входу
src/app/features/stations/data/ мокові дані та store
src/app/features/stations/types/ інтерфейси та типи
src/app/features/stations/config/ правила розрахунків, карта, тексти та графіки
src/app/features/stations/utils/ чисті розрахунки та побудова графіків
src/app/shared/config/          палітра кольорів і формати дат
src/app/shared/utils/           дати та застосування теми
src/styles/                    розміри, брейкпойнти та спільні статуси
src/app/features/stations/components/ shell, список станцій, карта та деталізація
src/app/shared/chart/components/ canvas-компонент, панель і модальний перегляд
src/app/shared/chart/config/    спільні налаштування графіків
src/app/shared/chart/types/     інтерфейси та типи графіків
```

Компоненти мають окремі `.ts`, `.html` і `.scss` файли (кореневий компонент не потребує власних стилів). Кольори змінюються в `src/app/shared/config/theme.config.ts`: та сама палітра використовується CSS, Chart.js і Leaflet.

Модульність реалізована через feature-папки та standalone-компоненти, без NgModules.

## Продуктивність та обчислення

Маршрути завантажуються ліниво; карта й canvas-графіки через `@defer`. Chart.js реєструє тільки потрібні контролери, шкали та плагіни. Графіки оновлюються без анімації та перестворення canvas. Map, ResizeObserver і chart instances очищаються при знищенні компонентів.

Store створюється на рівні захищеного shell та кешує розрахунки всіх станцій. `computed` кешує фільтри, архів та конфігурації графіків; `@for` відстежує стабільні ідентифікатори. Базова лінія обчислюється рухомим вікном за O(n) після сортування замість O(n²) у прототипі.

База — середнє попередніх 28 календарних діб, поточна доба виключена; потрібно щонайменше 14 валідних спостережень. Доби з тиском нижче 1 бар або відсутнім тиском виключені з бази й позначені як зупинка. Пороги — строго понад +25% та +30%. Відхилення під час зупинок залишається на графіку. Місячний графік охоплює останні 6 місяців від опорної доби незалежно від фільтра. Дати обчислюються в UTC.

## Перевірки

```sh
npm run build
npm test -- --watch=false
npm run test:e2e
npm run test:e2e:production
```

E2E за замовчуванням використовує встановлений Microsoft Edge у headless-режимі та піднімає локальний dev server. Для іншого браузера змініть `channel` у `playwright.config.ts`. Скриншоти пишуться в `test-results/`.

`test:e2e:production` збирає production-версію та перевіряє її на локальному SPA-сервері. `npm run preview` відкриває готову збірку на `http://127.0.0.1:4200`. CSS Leaflet завантажується лише під час відкриття карти; файли стилів та зображень копіюються в `assets/leaflet/`. Рядки журналу повторно використовують уже відформатовані дані таблиці.

## Vercel

Імпортуйте GitHub-репозиторій у Vercel із кореневою директорією проєкту `./`. Налаштування вже задані у `vercel.json`: Angular, `npm ci`, `npm run build`, вихідна директорія `dist/monitoring/browser` і SPA rewrite для вкладених маршрутів. Node.js має бути версії 22; мінімальна підтримувана версія зазначена в `package.json`.

Для цього демо змінні середовища не потрібні. Після деплою перевірте пряме відкриття `/login`, `/stations/kroshnya` та перезавантаження деталізації після входу. Локальний preview перевіряє збірку, але не замінює перевірку опублікованого URL Vercel.

## Межі демо

Дані та авторизація локальні. Сесія живе в `sessionStorage` поточної вкладки; пароль не зберігається. Клієнтські guards не забезпечують серверну безпеку. Для реальних даних потрібні backend authentication і перевірки доступу на сервері. Карта потребує мережевого доступу до OpenStreetMap; решта функцій використовує локальні дані. Для SPA-хостингу налаштуйте fallback усіх маршрутів на `index.html`; статична збірка знаходиться в `dist/monitoring/browser/`.
